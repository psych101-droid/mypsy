1. Product overview
1.1 What this app is
The MyPsych is a web-based journaling and self-discovery tool for people who want to understand themselves better through the lens of psychology. It is powered by an AI layer built on the Anthropic API (Claude), with a knowledge base drawn entirely from David Webb's published content across two sources:

All About Psychology Substack (allaboutpsychology.substack.com) — personal, applied psychology writing published weekly since 2024
All About Psychology website (all-about-psychology.com) — comprehensive psychology reference content published and updated since 2008

The app is not a therapy tool. It does not diagnose, treat, or offer clinical advice. It is an intelligent, psychologically-grounded journaling companion that helps users reflect, gain insight, and understand their thoughts and behaviours — guided by real psychological frameworks explained in David's voice.

1.2 The core value proposition
Every journaling or wellness app on the market is psychology-lite. This app is different because every prompt, concept explanation, and insight it surfaces is grounded in 18 years of David Webb's psychology content. The AI doesn't invent generic wellness advice — it draws on a real, trusted, expert knowledge base. That's the moat.

1.3 Target users
General public with a personal interest in psychology and self-understanding
Psychology students who want to connect academic concepts to real self-reflection
People who want to improve their day-to-day mental wellbeing through structured reflection

2. Content and knowledge base
2.1 Sources
The app's AI layer must be grounded exclusively in David's published content. No generic psychology databases, Wikipedia, or third-party sources. The two approved sources are:

Source A: All About Psychology Substack
Feed URL
https://allaboutpsychology.substack.com/feed

Access method
Live RSS feed — all articles are free so full content is available

Initial load
One-time export file provided by David at build time (covers full 18-month archive). See Section 9 for pre-build checklist.

Ongoing sync
Automatic RSS poll every 24 hours. New articles ingest automatically with no manual action required.

Source B: All About Psychology website
Base URL
https://www.all-about-psychology.com/

Access method
Crawl and index relevant pages on first build. Re-crawl periodically (weekly suggested).

Include
Psychology topic pages, history pages, classic articles section, expert interviews, student resources, What is Psychology, Types of Psychology, Abnormal Psychology, Biological Psychology, and all substantive educational content pages

Exclude
Memes, GIFs, cartoons, jokes, guestbook, disclosure/privacy policy, contact form, partner/sponsor pages, Amazon store links, any page whose primary content is images or entertainment rather than educational text

Important: The website content provides deep reference material. The Substack content provides David's personal, applied voice. Both are needed — they serve different purposes in the knowledge base.

2.2 RAG architecture (how the AI uses this content)
The app must use Retrieval-Augmented Generation (RAG) so that the AI draws on relevant content rather than dumping everything into every request. The implementation should work as follows:

On first launch, all content from both sources is chunked, embedded, and stored in a vector database
When a user writes a journal entry or requests a prompt/insight, the app performs a semantic search across the vector store to retrieve the 3-5 most relevant content chunks
Only those retrieved chunks are passed to the Claude API as context, along with the user's input
Claude generates a response grounded in that specific content — it should feel like David's knowledge, not generic AI output
The vector store updates automatically when new Substack articles are ingested via RSS

Suggested stack for RAG: Pinecone or Supabase pgvector for vector storage. Use OpenAI Ada or Claude's embedding endpoint for embeddings. Chunk size: approximately 400-600 tokens with 50-token overlap.

3. Core features
3.1 Guided journal
The primary feature of the app. Users write journal entries in response to psychologically-grounded prompts.

Each session begins with a prompt generated by the AI based on the user's recent entries, mood check-in, or chosen theme
Prompts are drawn from real psychological frameworks present in David's content — CBT patterns, attachment theory, cognitive distortions, values clarification, emotional regulation, self-determination theory, etc.
The prompt should always include a brief, plain-English explanation of the psychological concept behind it — written in David's voice, sourced from the knowledge base
Users write freely in response. There is no minimum or maximum length.
After the user submits an entry, the AI offers a short reflection — 2-4 sentences identifying any patterns, connecting the entry to a relevant psychological concept, or offering a gentle reframe. This must be grounded in retrieved content, not invented.
Users can optionally ask a follow-up question about the concept behind their prompt

The tone of all AI output must be warm, curious, and non-clinical. Think thoughtful educator, not therapist. David's Substack voice is the reference — read several articles before setting the system prompt.

3.2 Mood and theme check-in
A lightweight entry point before journaling that helps the AI personalise the session.

Simple mood slider or emoji-based selector (not a clinical scale — keep it accessible and friendly)
Optional theme selector: e.g. Relationships, Work & Motivation, Identity & Values, Emotions, Habits & Behaviour, Social Life — these map to areas well-covered in David's content
Check-in data is used to inform prompt selection and is stored for pattern tracking

3.3 Insight and pattern tracking
Over time the app surfaces patterns in what the user journals about.

Weekly summary: a short AI-generated paragraph reflecting on themes that appeared in the week's entries
Recurring themes: visual indicator of topics that appear frequently (e.g. anxiety, relationships, motivation)
Mood trend: simple line chart of mood check-ins over time
'This week in psychology': one relevant concept from David's content surfaced each week, connected to the user's recent themes

Keep visualisations simple and non-alarming. This is not a mental health monitoring tool — it's a curiosity and self-discovery tool. Frame everything positively.

3.4 Psychology concepts library
A searchable, browsable library of psychological concepts drawn from David's content.

Each concept has a title, a plain-English explanation (sourced from the knowledge base), and a link to the original article or page it came from
Concepts are tagged by theme (e.g. Cognitive, Social, Developmental, Clinical, Personality)
Users can save concepts to a personal favourites list
Concepts referenced in journal prompts or AI reflections link directly to their library entry
Free tier: browse and read concepts. Paid tier: full access including saved favourites and links to full articles

3.5 Daily prompt (optional standalone feature)
A short daily psychology prompt delivered as a push notification or displayed on the app home screen. One sentence. No journaling required — just something to think about during the day. Drawn from David's content. Can be the user's entry point into a journal session if they choose.

4. AI layer specification
4.1 Model
Use the Anthropic API. Model: claude-sonnet-4-20250514. Do not use a cheaper/faster model for the reflection and insight features — quality matters here. Standard prompt/response calls only (no streaming required for v1).

4.2 System prompt
The system prompt sets the voice and constraints for all AI output in the app. It must include:

Identity: You are a psychology guide built on the writing and knowledge of David Webb, creator of All About Psychology. You help users reflect on their thoughts, feelings, and behaviours through the lens of psychology.
Voice: Warm, curious, accessible, non-clinical. Speak like a knowledgeable friend, not a therapist or textbook. Use David's Substack articles as your voice reference.
Constraint: Only draw on the provided context documents when making psychological claims or explaining concepts. Do not invent frameworks or reference sources not in the knowledge base.
Safety: If a user's entry suggests distress, crisis, or self-harm, do not attempt to provide support yourself. Acknowledge warmly and direct them to appropriate professional resources (e.g. a GP, therapist, or crisis line). You are a reflection tool, not a mental health service.
Scope: Do not offer diagnoses, clinical interpretations, or treatment recommendations under any circumstances.

4.3 Prompt generation
When generating a journal prompt for a user, the AI should:

Take the user's mood check-in and chosen theme (if provided) as input
Retrieve the 3-5 most semantically relevant chunks from the vector store
Generate a prompt that is specific (not generic), grounded in a named psychological concept, and includes a 1-2 sentence explanation of that concept in plain English
Format: Concept name (bolded) + one-sentence explanation + the actual reflective question

Example output format: Cognitive dissonance — the discomfort we feel when our actions don't match our beliefs. Think of a recent decision you made that felt slightly 'off.' What were you telling yourself to justify it?

4.4 Post-entry reflection
After a user submits a journal entry, the AI generates a short reflection. Rules:

Maximum 4 sentences
Must connect something specific from the user's entry to a psychological concept from the knowledge base
Tone: curious and affirming, never evaluative or prescriptive
End with an optional follow-up question the user can explore if they want to go deeper
Always include the name of the concept being referenced and a link to its library entry

5. Design and UX
5.1 Platform
Web app, mobile-first responsive design. Must work well on iPhone/Android browsers without requiring a native app download. A clean, installable PWA (Progressive Web App) setup is ideal so users can add it to their home screen.

5.2 Visual identity
The app should feel calm, intelligent, and trustworthy — consistent with the All About Psychology brand. Design reference: allaboutpsychology.substack.com and all-about-psychology.com.

Colour palette: draw from the existing brand. Deep navy/blue tones, clean white backgrounds, warm accent colour. Nothing clinical or cold.
Typography: clean, readable sans-serif for body text. Slightly warmer serif option for journal entry areas to encourage a writing mood.
No gamification, streaks, badges, or points. This is a reflective tool, not a habit app.
No ads. Ever.
Minimal UI — the writing surface should dominate. Keep chrome and navigation unobtrusive.

5.3 Key screens
Home / dashboard
Today's prompt, mood check-in, recent entry summary, weekly insight if available

Journal entry
Full-screen writing surface, prompt displayed at top, submit button, post-entry reflection appears below

Concepts library
Searchable, filterable grid of psychological concepts. Tap a concept to read its explanation and see linked articles.

Insights
Mood trend chart, recurring themes, weekly summary paragraph

Settings
Account, subscription, notification preferences, data export

6. Suggested tech stack
This is a recommendation, not a hard requirement. Fable 5 / Claude Code should use its judgment on implementation details. The non-negotiables are: Anthropic API for AI, RAG architecture for content retrieval, and web-first deployment.

Frontend
Next.js (React) — good for mobile-first PWA, fast rendering, easy deployment

Backend
Next.js API routes or a lightweight Node/Express API

Database
Supabase (Postgres) — handles user data, journal entries, mood logs. pgvector extension for RAG vector storage, removing the need for a separate vector DB.

AI
Anthropic API — claude-sonnet-4-20250514

Embeddings
Voyage AI or Anthropic embeddings for content chunking and vector search

Auth
Supabase Auth (email + magic link — keep friction low)

Payments
Stripe — subscription billing, one-time purchase option

Deployment
Vercel — zero-config Next.js deployment

RSS ingestion
Background cron job (Vercel cron or similar) polling the Substack RSS feed every 24 hours

7. Data and privacy
Journal entries are deeply personal. Data handling must be treated with care and communicated clearly to users.

Journal entries are stored securely and are never used to train AI models
Entries are private to the individual user — David Webb and the app team cannot read them
Users can export all their data at any time as a plain text or JSON file
Users can permanently delete their account and all associated data
No journal content is ever sent to third parties. The Anthropic API call includes only: the system prompt, the retrieved knowledge base chunks, and the user's current entry — nothing from historical entries unless the user explicitly chooses to include context
GDPR compliance required. David's audience includes significant numbers of EU/UK users.
Clear, plain-English privacy policy required before launch

8. Out of scope for v1
The following are explicitly excluded from the first version to keep scope manageable:

Native iOS or Android app (PWA is sufficient for v1)
Social features, community, or sharing of any kind
Therapist or clinician-facing tools
Audio or video content
Multi-language support
Integration with wearables or third-party health apps
In-app content publishing by David (the Substack/website sync handles this automatically)
